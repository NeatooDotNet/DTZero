# v2.0.0 — DTZero

**Release Date:** 2026-11-11
**NuGet:** [DTZero 2.0.0](https://nuget.org/packages/DTZero/2.0.0)
**Breaking changes:** Yes. Every public name changes. Update client and server together.

## Overview

Zero DTOs. This is the first release under the DTZero name. The library behaves exactly as v1.10.9 did, and every change in this release is a rename.

## What's New

Nothing new for application code.

## Breaking Changes

| Area | Name in this release |
|---|---|
| Packages | `DTZero`, `DTZero.AspNetCore` |
| Root namespace | `DTZero` |
| Registration | `AddDTZero`, `AddDTZeroAspNetCore`, `UseDTZero` |
| Public types | The `DTZero` prefix, such as `DTZeroFactory`, `DTZeroRuntime` and `DTZeroServices` |
| Endpoint | `/api/dtzero` |
| Headers | `X-DTZero-Format`, `X-DTZero-Not-Authorized` |
| Trimming feature switch | `DTZero.IsServerRuntime` |
| Log categories | `DTZero`, `DTZero.*` and `Trace.DTZero` |

`NF` diagnostic codes do not change.

## Bug Fixes

None.

## Migration Guide

The compiler finds the namespaces, types and registration calls. It does not find these, so check them by hand:

- **The endpoint and headers.** A client and server on different versions cannot talk to each other, so deploy them together. Update anything that names the route or the headers, such as middleware, proxies and firewall rules.
- **The trimming feature switch.** A switch set under its earlier name is ignored without an error, and the client then keeps its server-only code. Set `DTZero.IsServerRuntime` in the client project.
- **Log filters.** A filter on the earlier category names stops matching, without an error.
