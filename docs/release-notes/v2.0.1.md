# v2.0.1 — Inherited authorization checks are enforced

**Release Date:** 2026-11-16
**NuGet:** [DTZero 2.0.1](https://nuget.org/packages/DTZero/2.0.1)
**Breaking changes:** No API change. A project affected by the fix below changes behavior: read "Who is affected".

## Overview

A security fix. An authorization check that the auth type named in `[AuthorizeFactory<T>]` inherited, and did not declare itself, was not enforced. Nothing reported it. The check is now enforced, and a check the generator cannot enforce fails the build.

## What's New

- **A shared authorization base works.** Declare a broad check once, on a base interface or an abstract base class, and let each type's auth class inherit it. Only the auth type the factory names is registered.
- **NF0107** (error): an authorization check is declared in a referenced assembly, so the generator cannot read it. Declare the check on the auth type, or on another type in the same project.
- **NF0108** (error): an authorization check cannot be called on the auth type, because the class implements it explicitly or leaves it to a default interface implementation. Implement it as a public method, or name the interface in `[AuthorizeFactory<T>]`.

## Breaking Changes

None in the API.

## Bug Fixes

- **Security: a check inherited from a base interface was dropped.** With `interface IOrderAuth : IBaseAuth`, the `[AuthorizeFactory]` methods on `IBaseAuth` produced no check and no diagnostic. They are now enforced like the methods `IOrderAuth` declares.
- **Security: a check on an interface was dropped when the factory named the implementing class.** With `[AuthorizeFactory<OrderAuth>]` and the `[AuthorizeFactory]` methods on an interface `OrderAuth` implements, no check was generated. They are now enforced.
- **A check on an abstract base class stopped the server at startup** with "Cannot instantiate implementation type". Every check is now resolved through the auth type the factory names.
- **A check reachable by two inheritance paths runs once.** A check a derived auth class overrides runs the derived version, once.
- **An explicitly implemented check failed the build inside generated code** with CS1061. It is now NF0108, reported at the `[AuthorizeFactory<T>]` attribute.

These apply to class, interface and static factories.

## Who is affected

Generated code is unchanged for an auth type that declares all of its own checks. That is every shape the documentation showed before this release.

A project is affected if an auth type inherits a check, or if a factory names a class whose checks sit on an interface it implements:

- **Those checks were not running. They run now.** A caller they refuse is refused, where before the call went through. Review what those callers could reach.
- **The build may fail with NF0107 or NF0108.** Each message names the auth type and the check, and says what to change.
- **A refusal names the auth type the factory uses**, not the base type that declares the check, in the `NotAuthorizedException` message.

## Known Limits

- A generic base auth interface, such as `IAuthBase<TEntity>`, is not supported. The generated code is expected not to compile.
- Two unrelated base interfaces that declare the same check are read as one check. The generated call is expected not to compile.

## Commits

- `fix(generator): enforce inherited authorization checks`
- `fix(generator): enforce checks on interfaces an auth class implements`
